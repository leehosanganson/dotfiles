# Background subagents

Pi uses `pi-subagents@0.90.0` for detached background workers. The parent session keeps the selected main model, remains in charge of Autopilot, and receives worker completion reports without waiting for each child.

## Jev routing

The System One extension intercepts direct `subagent` launches and asks the configured Jev model to score task risk and choose a worker model. It fails closed unless the dedicated `litellm/openrouter/jev-1.14` decision model is configured and available. A decision is accepted only when its confidence is at least `0.70`; missing, invalid, or lower-confidence results block the launch. Risk is a normalized score from `0` to `1`, and scores at or above `0.70` go to the read-only `planner` agent. Its preferred model is `litellm/chatgpt/gpt-6.2-astra`, followed by the approved models in `PLANNER_MODEL_PRIORITY` in `pi/system-one/src/subagent-policy.ts`. This is an operator-selected preference order, not a measured intelligence ranking.

After reading the planner's result, the parent decides whether to continue. For a later implementation launch, the parent sets the accepted package field `label` to `plan reviewed`; the router still scores the task and selects an approved worker model. This marker records the parent session's decision. It is not a human approval, and it does not bypass Autopilot or repository approval rules.

The approved worker model preference order is `litellm/openrouter/gpt-6-luna`, `litellm/openrouter/deepseek-v4-flash`, `litellm/chatgpt/gpt-6-luna`, `litellm/chatgpt/gpt-6.2-sol`, `litellm/chatgpt/gpt-6.2-astra`, and `litellm/unsloth/qwen-3.8`. Jev can choose any item in this pool. OpenRouter-backed models are preferred for availability; ChatGPT-backed models consume a limited weekly quota; Qwen is the free, lower-performing last choice.

The user-scope `worker`, `explorer`, and `evaluator` agents are available to `pi-subagents`. The worker keeps its normal implementation tools. Explorer and evaluator have only `read` and `ls`; a Pi-only child extension checks each file-tool call before execution and blocks paths outside the active project, symlink escapes, common secret-file names and directories, and hidden `.pi` configuration directories. Recursive `grep` and `find` are not available to those two agents. This is a narrow tool boundary, not an operating-system sandbox; it cannot identify every secret stored under an ordinary project filename. Keep sensitive files out of their tasks and add stronger isolation before using them on repositories that contain untrusted or high-impact secrets. User agent definitions need a `name` in their frontmatter for `pi-subagents` to discover them; Pi-specific tool restrictions and the guard extension belong in `settings.json`.

Use separate single-child calls to run several agents in parallel. The policy blocks parallel arrays, chains, workflow scripts, and their internal child-launch tool because the parent cannot score each nested child before launch. Nested delegation is limited to one level. The router selects only from user agents, not project-defined agents.

## Failure handling and limits

Jev errors, invalid answers, or uncertain decisions fail closed: the worker does not start. The parent can clarify the task or choose the next step under its normal authority.

The planner model list is an ordered retry list, not automatic failover: `pi-subagents` returns a provider error, including HTTP 429, instead of trying another child model. If a planner launch fails, the parent can retry the same high-risk task with the next approved model from `PLANNER_MODEL_PRIORITY` in the `model` field; the policy keeps the planner agent and planning-only task while accepting only listed models. Workers still use Jev's single selected model, not this retry list. Actual automatic quota fallback must be configured and verified in the deployed LiteLLM gateway. That configuration is outside this repository and remains unverified; do not treat either model preference as gateway failover.

The package is pinned in `pi/.pi/agent/settings.json`. Restart Pi to load the package and router changes. A controlled low-risk live test confirmed Jev-gated background launch and result delivery through `scout`; it returned the expected heading, but the package's structured acceptance check was rejected because the worker did not provide its report. A separate high-risk read-only test confirmed Jev routed the task to `planner` and accepted the user-selected `litellm/openrouter/gpt-6-luna` model override; the planner completed and its structured acceptance was attested. This verifies the manual override path, not automatic retry after an Astra provider failure. Deployed gateway fallback remains unverified.
