# Visual parity

**Trigger:** Matching an implementation to an authoritative screenshot or visual reference.

1. Confirm the reference is authoritative and establish reproducible viewport, application state, and data.
2. Capture both the reference and current implementation under comparable conditions.
3. Compare at component level—layout, typography, spacing, and color—and identify the largest meaningful mismatch.
4. Adjust the implementation, then capture and compare again until acceptance criteria are met.
5. Preserve accessibility, responsive behavior, and project conventions while matching the reference.

**Boundary:** This is for parity work only; use `/frontend-design` for a new visual direction. Do not claim pixel parity without direct visual comparison.
