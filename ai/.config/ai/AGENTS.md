# Shared AI workflow entry point

Keep this directory vendor-neutral: its skills, agents, prompts, and playbooks describe outcomes and workflows, not any particular model provider, agent harness, command syntax, tool name, frontmatter schema, or installation path. Put runtime-specific configuration and adapters in the corresponding runtime's configuration directory. Preserve upstream license and attribution files as legal metadata, not prompt guidance.

For substantive tasks, use the `/autopilot` skill as the workflow entry point. It selects a task playbook; playbooks sequence capability skills and identify relevant `principle-*` skills. Write callable skill references as `/skill-name` and identify workflows with `Playbook: name`. Leaf skills are the canonical actionable guidance and can be used by delegated agents. Autopilot's references hold workflow routing and indexes, not duplicate copies of leaf skill content.

Load only context relevant to the current task and decision; avoid preloading whole skill or tool catalogs. Defer stage-specific guidance until its owner needs it. Keep simple questions and one-step tasks lightweight.

Keep the main thread focused. For every substantive software task with a lifecycle workflow, the main agent owns the lifecycle and active stage: clarify the goal and decisions, select the playbook, plan and perform the stage work, and track concrete tasks in the current harness's native todo mechanism. Use todos in this form: `(Task Name) - Stage (Plan/Implement/Test/...): (Description)`. Keep stage sequencing, acceptance criteria, approval gates, integration and reconciliation, and final verification with the main agent. Delegate only bounded, useful tasks when they reduce effort or improve independent evidence; do not hand off an entire stage or its ownership. Contributors load the guidance relevant to their assigned task, stay within scope, and return findings or work with concise evidence. Contributors do not need to delegate or spawn other contributors. Advance dependent stages sequentially and mark tasks complete only when their acceptance evidence exists. The main agent owns user-facing clarification and session-pickup coordination: rebuild the task from session evidence and live state, reconcile completed and pending work, blockers, and active processes, resolve conflicts using current evidence, and choose or confirm the next step. Load only relevant guidance for the work at hand. For simple questions and genuine one-step tasks with no lifecycle, respond directly.

Use the current runtime's native skill invocation to activate `/autopilot`, then follow the matching playbook. The main agent owns each active stage and records concrete work in native todos; delegate bounded, independently useful tasks only when practical, with the relevant playbook, skills, evidence, scope, and acceptance criteria. An explicit autopilot invocation for implementation means carry the task through verification to a reviewable PR, including task-scoped commits, branch push, and PR creation without redundant approval prompts. It does not authorize merging, deployment, or unrelated changes. Keep simple questions and one-step tasks lightweight.
