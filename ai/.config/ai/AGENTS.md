# Shared AI workflow entry point

Keep this directory vendor-neutral: its skills, agents, prompts, and playbooks describe outcomes and workflows, not any particular model provider, agent harness, command syntax, tool name, frontmatter schema, or installation path. Put runtime-specific configuration and adapters in the corresponding runtime's configuration directory. Preserve upstream license and attribution files as legal metadata, not prompt guidance.

For substantive tasks, use the `autopilot` skill as the workflow entry point. It selects the task playbook; playbooks sequence capability skills and identify relevant `principle-*` skills. The leaf skills are the canonical actionable guidance and can be used by delegated agents. Autopilot's references hold workflow routing and indexes, not duplicate copies of leaf skill content.

Load only context relevant to the current task and decision; avoid preloading whole skill or tool catalogs. Defer stage-specific guidance until its owner needs it. Keep simple questions and one-step tasks lightweight.

Keep the main thread focused. For every substantive software task with a lifecycle workflow, the main agent is strictly the router/coordinator: classify the request, select the playbook and current stage, and delegate that stage's work to a subagent. Do not perform a stage inline merely because it is coupled, overhead seems high, or a skill normally runs inline. The assigned subagent owns the stage and loads its playbook, stage skill, and selected capabilities. Advance dependent stages sequentially with fresh stage owners and concise exit-evidence handoffs. Keep user clarification, stage routing, approval gates, sequencing, result reconciliation, and final integrated verification with the coordinator. Load only routing context in the main thread; do not preload stage guides or capabilities that belong to delegated owners. For simple questions and genuine one-step tasks with no lifecycle, respond directly. If delegation is unavailable, state the limitation and ask before proceeding inline unless the user already authorized that fallback.

Use the current runtime's native skill invocation to activate `autopilot`, then follow the matching playbook. Load only relevant routing guidance in the main context. For every active lifecycle stage, delegate execution and pass the assigned playbook, stage skill, capability and principle skills, relevant evidence, scope, and exit criteria; direct the subagent to load its guidance and return concise evidence. An explicit autopilot invocation for implementation means carry the task through verification to a reviewable PR, including task-scoped commits, branch push, and PR creation without redundant approval prompts. It does not authorize merging, deployment, or unrelated changes. Keep simple questions and one-step tasks lightweight.
