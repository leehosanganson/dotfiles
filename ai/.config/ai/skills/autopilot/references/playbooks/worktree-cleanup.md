# Worktree cleanup

**Trigger:** The user asks to reclaim disk or remove Git worktrees and related stale development artifacts.

1. Inventory worktrees, their local branches, status, PR state, remote-tracking branches, and candidate artifacts using read-only commands. Show each exact candidate and why it qualifies. Invoke `/principle-temp-files` when temporary or scratch artifacts are candidates.
2. Invoke `/principle-prove-it-works` to verify each candidate's branch, PR, and remote state. Preserve any worktree with uncommitted changes, an active task, unknown ownership, or uncertain status. A branch with no PR raised must be preserved, even if its worktree is clean and it has a remote branch.
3. A worktree and its local branch are eligible for removal when either (a) its PR is confirmed merged, the worktree is clean, and the local branch is merged into the intended base; or (b) a PR has been raised, the worktree is clean, and the local branch's commits are fully represented by an available remote-tracking branch. For case (b), verify the remote branch preserves the local branch tip before removing the local copy. Do not treat a closed, unmerged PR with no surviving remote branch as safe. Never delete a remote branch as part of local worktree cleanup.
4. Treat a cleanup request as authorization to remove candidates meeting these criteria; no extra confirmation is needed for those local removals. Remove the worktree first; delete its local branch only afterward, once no worktree is using it. For case (b), force-deletion of the local branch is acceptable only after verifying the remote-tracking branch contains the exact local tip and all local commits, so no unique work is lost. Never remove remote branches. Obtain explicit confirmation for candidates involving irreversible destructive behavior or uncertain state, naming exact paths and branch names. Re-list worktrees and branches and verify each removal without affecting active work.
