# Delegate implementation

**Trigger:** The user has authorized implementation and the work has independently scoped slices that benefit from subagents.

1. Gather relevant project context and settle scope, constraints, assumptions, and measurable acceptance criteria. Draft plausible work slices and identify dependencies, shared files/state, context-transfer cost, and task risk before judging delegation; System One cannot create the factual decomposition for you.
2. When the speed/cost tradeoff is genuinely uncertain and a bounded decision capability is available, use it with that evidence and batch these judgments: (a) which strategy fits best—lead-only, one bounded agent, parallel agents, or none; (b) whether delegation is likely to reduce elapsed time versus lead-only; and (c) whether it is likely to reduce total model cost versus lead-only. Include concrete candidate slices, model assignments, and coordination overhead in the supplied state. Treat the answer as advice, not authorization. Do not call a judge for an obvious one-step or mechanically determined choice.
3. Use the recommendation to choose a proportionate approach: parallelize only if slices are independently useful and likely to save meaningful time; delegate serial work only when it removes enough lead effort or otherwise improves the task's time/cost tradeoff. If the estimate is equivocal, the slices are weakly bounded, or expected coordination cost outweighs the benefit, keep work with the lead. Speed and lower total cost are separate outcomes; report when pursuing one is expected to trade off against the other rather than claiming both improve.
4. Split approved work into vertical slices with explicit interfaces, permitted files, exclusions, dependencies, risks, and verification steps. Assign one owner per mutable file/state and serialize conflicts. Keep hard boundaries deterministic: no conflicting writes, no unapproved external/irreversible actions, and no worker outside its assigned scope regardless of judge output.
5. Follow the delegation skill or instructions available in the current runtime for dispatch and handoff; this playbook owns the delegation decision. Assign separate implementation and independent-review roles when appropriate. Select models using the runtime's configuration and available capabilities; retain stronger reasoning for ambiguous or high-risk work and final review when the available models warrant it. Do not claim delegation if a task was implemented by the coordinator.
6. Integrate in dependency order. Inspect actual diffs, reconcile conflicts against the brief, and return incomplete or out-of-scope work for correction.
7. Verify the combined result, including cross-slice behavior, relevant tests/checks, safety constraints, and final diff scope. Report the decision and rationale, chosen model(s), observed usage/cost when available, and any speed/cost tradeoff or limitation.

**Boundary:** Do not delegate a single bounded task, planning-only work, or slices with unresolved dependencies. If delegation is unavailable, say so and proceed inline only when appropriate.
